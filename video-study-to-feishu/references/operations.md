# 获取材料与飞书交付

按当前任务阅读需要的部分。工具和平台会变化，优先发现当前可用连接器、相关 skill 与 CLI 帮助，不固化旧版本假设。

## 视频和字幕

1. 先确认单条视频 ID、标题、发布者、时长、语言，以及用户给出的课件。URL 包含播放列表或 Watch Later 但指定一条视频时，只处理该视频；明确的播放列表任务才按用户指定范围处理。
2. 可用连接器、网页 transcript 或 yt-dlp 都可作为获取入口。下载前列出字幕；人工字幕通常优先，仍检查与音画是否对应。选原语言字幕避免把自动翻译当原话；中文整理保留必要原文术语。
3. yt-dlp 的公开字幕起点如下，先查看本机 `--help` 和实际语言标签，再选择具体轨道：

```bash
yt-dlp --no-playlist --skip-download --list-subs 'VIDEO_URL'
yt-dlp --no-playlist --skip-download --write-subs --write-auto-subs \
  --sub-langs 'SELECTED_LANGUAGE' --sub-format 'json3/vtt/best' \
  -o 'source/%(id)s.%(ext)s' 'VIDEO_URL'
```

把示例值替换为真实目标及语言后再执行。json3、VTT、SRT 都需要保留原时间范围，去除滚动字幕重叠并合并完整语句，避免机械逐行摘要。

4. 若遇登录验证，先考虑不使用身份信息的公开访问途径。读取浏览器 cookies 需要针对确切视频的明确授权；授权不延伸到另一个视频，不输出或导出 cookies。用户已经明确授权同一视频时不重复询问。不主动修改登录状态或扩大访问范围。
5. 没有可用字幕时，转写可访问的音视频。当前环境可用飞书妙记时使用 lark-minutes，遵循其上传与逐字稿流程；其他转写能力按实际工具条件选择。说话人区分与时间对齐须检查，不能假定字幕天然包含可靠的 speaker ID。
6. 验证失败后选择一个有依据的替代路径。相同原因持续失败时停止重复请求，说明所缺材料，继续能完成的部分。未获取的章节不根据标题或外部摘要补写。

## 画面覆盖

有原始 PDF / PPT 时先浏览完整课件，再与视频的顺序和动画对齐；原文件可补足被讲者窗口遮住的内容。原文件与演讲版本不同时注明实际差异。

只有视频时，按画面变化定位候选片段，做联系图或全片通览，再自适应加密抽帧。自动 scene change、固定间隔或 OCR 都只是候选发现方法：静态布局内的新增说明可能没有明显场景变化，必须检查内容是否完整展开。字幕主题变更处、静音区和结尾都要看。

内部可记录如下字段，便于补漏和图文对齐：

| 时间范围 | 页面或场景 | 新增信息 | 位置 |
|---|---|---|---|
| 起止时间 | 图名、步骤或主题 | 与上一状态相比的知识增量 | 正文、画面索引、纯重复省略 |

每个包含新知识的画面都应有去向。标题、纯装饰、重复画面、无关广告及只改变手势或光标的状态不强行保留。连续演示用关键操作、状态变化与结果帧重建过程，不要求保存每一帧。

裁剪可以改善可读性，但不裁掉图例、坐标、单位、条件或关键箭头。遮挡影响结论时尝试寻找同页其他时刻或原课件；仍不清楚就保留明确缺口，不凭字幕补造数值。时间链接始终对应原视频。

## 飞书写入

使用 lark-doc，按其路由读取所需的 lark-shared、fetch、create / update、XML 和媒体插入说明。没有相关 skill 时，发现实际工具并查看帮助；内容写入与权限修改分别按用户授权处理。创建笔记不附带公开分享、群发或修改权限的授权。

- 用户指定更新目标时，先读目标结构，在原文档中维护。用户将自己的笔记留作独立对照时另建一份。没有目标则新建一份，不反复创建多个试验文档。
- 默认一个文档包含导读、主题笔记、按章节整理的重要画面及 Q&A。用户明确只要短摘要时按其范围交付，不强制附全套课件；材料访问受限的降级版在开头用一句话说明。
- 长文先建骨架，取实际章节 ID 再按章写入。结构变化后刷新受影响的 block ID。媒体插到实际对应段落或图注处；不要只在末尾堆图。
- 以 CLI `ok == true` / 退出状态及回读为准，不把返回信封当页面效果。回读检查主旨可见、章节有序、图片可读且放置正确、链接可回到视频、重要画面和问答没有遗漏。
- 检查留在整理过程中，正文不附文件哈希、字幕条数、block ID、修复历史、授权经过或验收清单。用户要求处理审计时才另行提供。
- 最终交付链接及简短介绍。若云文档写入失败，可暂存本地并说明具体阻塞；确认发布成功前不声称已经生成飞书文档。
